### P1 — Any same-UID RPC client can clear an explicit compositor-lock latch

**Paths:** `python/src/hyprneuro/sidecar.py:284–293,600–613`; `python/src/hyprneuro/session_lock.py:47–58,136–151`.

The new RPC forwards `locked:false` to `session_lock_event()`, which clears `_explicit_lock`. Socket authentication establishes only the peer UID—not that the caller is the trusted compositor/session producer. Matching the session string supplies no additional authority.

**Verified reproduction:** set a trusted explicit lock while synthetic logind reports unlocked and procfs contains no recognized locker. Reconciliation correctly denies. Send `locked:false` through an actual same-UID Unix connection without a producer credential: the next reconciliation grants verification using the **unchanged** logind/procfs evidence.

This does not bypass those independent checks. It defeats the explicit latch precisely for hook-only lock mechanisms those checks cannot detect.

**Smallest correction:** make ordinary RPC notifications revocation-only; reserve clearing the explicit latch for the trusted host interface. Add a regression proving an untrusted false notification cannot clear a trusted lock even when logind/procfs otherwise appear unlocked.

### P1 — Verification can expire during the final focus query, yet capture still starts

**Path:** `python/src/hyprneuro/recall.py:368–375`; expiry implementation at `python/src/hyprneuro/session_lock.py:64–71`.

Discarding afterward does not prevent capture during uncertainty.

**Smallest correction:** recheck session admission immediately after the final focus query and before `grab()`. Add this delayed-query regression; the existing expiry test covers model-lane admission, not capture admission.
